# NonbiriAPI

[English](README.md)

NonbiriAPI 是可自行部署的 AI 端点管理平台，提供 OpenAI-compatible 调用入口。用户管理服务、端点及服务内的 API 密钥，按端点与密钥维护模型列表，通过可撤销的 CallerKey 调用个人或公益模型。可选活动和小游戏共用服务端权威的账务及生命周期规则。

**v1.3.2** 增加管理助手的 Codex 设备码来源，完善请求失败原因和管理操作详情，并修复协议续接。已有数据库需显式升级至 schema 42，账号导出保持格式 31。本版使用精确源码提交，不创建 tag 或 GitHub Release；构建方法见下文，版本沿革见 [CHANGELOG](CHANGELOG.md)。源码状态不代表实例已经部署。

## 架构

单个 Go 进程提供两套内嵌 React 站点和一个本地 SQLite 数据库。用户站与管理员站采用独立主机名及权限边界。生产目标为 Linux/amd64；Windows 用于开发和构建验证。

模型目录通过只读 SQLite 快照即时判断可用性，批量读取候选和近期成功率；个人模型列表也使用现有的有界读连接池。没有完整列表缓存或 TTL，用户身份、等级、捐赠归属和当前配额仍参与判定。实现约束见[数据库访问](docs/database-access.md)，运行指标见[部署指南](docs/deployment.md)。
可用绑定计数在每份绑定找到首个合格目标后停止，避免对等价目标重复检查权限与配额。

《垂钓手记》检查点在同一事务内复用权威数据，活动通知快照使用现有读池；版本号、重放回执和租约仍原子保存。[混合负载实验](docs/performance-validation.md)同时报告两池等待、真实检查点完成数及发压延迟。

写连接有界复用读写 SQL 的预编译语句，打开的结果游标保持独占；独立配置读取使用读池，当前完整内容相同时复用校验结果。每次调用仍读取数据库现值，账务、权限和可用性保持权威判定。

尝试与请求完成在并发积压时采用小批同步提交，持久化提交成功后才确认。匿名指标分别报告应用队列和数据库连接池等待。

[服务](docs/service-connections.md)包含端点与密钥；密钥可明确用于同一服务的多个端点，在其他服务不可见。拉取和手动模型列表按端点＋密钥独立维护。新建或编辑服务与捐赠时，授权所选协议的完整服务集合；既有捐赠在捐赠者再次编辑提交前保留原授权，已批准快照不会自动扩张。模型绑定按端点、密钥、模型分级多选，并保留适用调用方式。换密钥后，已批准的公益用途保留旧版本，新的版本另行审核。

新增服务默认只填地址与 API 密钥，可增加其他密钥；协议和特殊模型列表设置按需展开。保存后直接获取并管理模型，某一步失败时保留已完成内容并继续恢复。拉取失败保留上次成功结果，手动条目始终可维护。审核结果保留服务类型和遮罩密钥标签，成功批准且当前有维护权限时可继续配置到公益模型，保留手动调整；批量绑定按每个目标保存明确选定的服务子集。

审核人员可对整份当前待审内容一次通过或退回，并填写可选备注。后端检查完整待审版本集合，将决定、审计和回执一起提交；任一内容变化便整份不执行。未知结果使用原请求恢复，退回替换内容保留此前批准版本。具体启用哪些服务在公益模型绑定时选择。

创建自定义入口时会显示地址相符的当前主流预置详情，可明确采用其中一个入口，也可继续使用自定义草稿。提示不会自动授权凭据或批准捐赠。

注册表包含 13 种连接器，覆盖 OpenAI-compatible、专用 Chat 与 Responses、Anthropic、Gateway v3/v4、Gemini、Decisions、System One 及四种明确选择的 rerank 协议。两种 Gateway 版本均支持文本生成、图像生成、embeddings 和 rerank，使用完整端点地址，不自动探测版本。直接 HTTP 接口支持文本、图像、音频、嵌入、内容审核和重排，部分操作支持 SSE。Chat Completions 与 Responses 是独立的模型接口和绑定选项，已有有限双向转换按支持范围保留；其余服务仍可独立多选。[直接推理](docs/direct-inference.md)列出接口、转换限制和排除的持久资源／实时能力；所有权、凭据、SSRF、账务和取消规则见 [API 契约](docs/api-contract.md)。

公益价格支持按次、按 Token 和按 search unit 计费，可分别设置输入／输出模态价格、捐赠奖励和长上下文档位。标准分类不完整时，对应一侧使用聚合价格。[定价说明](docs/charity-context-pricing.md)解释精度、预留和失败生成的有效用量。轻重型请求各有一个自用与公益共用的并发池，公益 RPM 也分为两个窗口；所有请求继续共同受全局限额约束。

自用与公益模型共用[会话请求头代管控件](docs/charity-session-headers.md)，提供五种格式；0 秒为每条逻辑请求重新生成，内部重试复用，不保证绝对唯一。模型设置与请求适配分别保存。

有权读取请求适配配置的用户可查看未标记响应防回显的固定请求头和主体值；任何保护标记都会隐藏整项已保存值。保存回执和账户导出继续省略这些值。

管理员及 5／6 级协管的日志页显示[全站并发与 RPM](docs/api-contract.md#global-pressure)、近似 24 小时峰值和持久化最大观测值。只有确认来自原始未改参数的有限错误才保持捐赠密钥连续失败次数不变，模糊错误仍按原规则处理。

公益短请求的拒绝说明会以中文或英文解释最低长度要求。字符计数包括消息文本、工具说明、参数定义及历史调用参数；工具存在不豁免真正的短请求。Dry 调试仅提醒并继续捕获，不扣分、不计入自动限制；Live 调试和普通请求保留现行处罚。未来字段校验或协议转换失败会保存安全的字段、原因与修正提示，显示在本人日志及获授权管理视图和导出中，不记录提交值或秘密；没有历史原因的旧记录仍显示未知。

浏览器外观设置提供明亮、暗色、跟随系统及三档玻璃强度，手动选择优先。专注模式可临时查看完整背景，返回后恢复阅读表面。

匿名分钟指标分别记录游戏检查点、请求账务及后台维护的连接获取和事务执行；跨窗口尚未结束的工作也有累计占用时间。对照已完成请求延迟和当前占用时，请参阅运行指标说明。

可选的抽卡活动提供分层 SP 美术。「未命名的明天」包含一张 ChatGPT 卡和明暗动态站点装扮，奖池模板保持未发布。琥珀誓章装扮将人物放在桌面正文侧边，静态回退保持同样位置，并提供高清素材；构图及来源说明见[美术指南](docs/gacha-art.md)。

「糖夜迷藏」包含 ChatGPT、Claude 两张仅供成年人的 R-18 限定 SSR、主题插画与独立卡池封面，含成人裸露与透明服装，相关资源及其衍生随公开源码分发；未发布的奖池模板中，两张限定卡等权。管理员默认禁用 R-18 内置美术，禁用后显示替代图，收藏、抽卡结果与已保存偏好保留；详见[美术可用性](docs/gacha.md#artwork-availability)。

神秘商店的“量大管饱”提供 10 张常驻抽奖券和 10 张限定抽奖券，每件 10,000 悠哉积分，优先消耗游戏积分，每件每天各限购一次。管理请求日志支持直接按 Discord ID 精确筛选，“调用的公益模型”位于常用条件，“所用模型”位于更多条件。

获授权的管理人员可从日志直接进入对应公益模型，以及每次调用所用的捐赠密钥管理；返回后保留日志筛选与页码。

公益模型添加服务连接时，选中密钥后可直接重新拉取模型列表或管理该密钥，返回后保留当前选择。

公益调用会自动识别可恢复的额度错误，暂时等待后由下一次真实公益请求试用恢复，无需为每把密钥配置。管理员和获授权协管可按完整端点添加错误码或消息片段规则，同端点的公益密钥共用。有效重试响应头优先，其他错误仍遵循连续失败策略。恢复节奏和状态见[API 契约](docs/api-contract.md#413-smart-donated-key-backoff)。

5 级协管采用每人独立的 51 项操作权限、6 项数值上限和四档捐赠范围，由管理员或实际 6 级协管设置。标准档为默认：捐赠至少有一把未结束且未过期的密钥，并且每把这样的密钥均来自主流渠道或当前绑定主流公益模型，整份才符合范围。增强档额外包含任意端点带管理标签的整份捐赠，完全访问采用 6 级资源范围，无则关闭捐赠访问。审核、标记和维护共用整份范围，仍需各自操作授权；身份可见性另行授权。安全的用户捐赠历史读取独立于操作范围。全部撤权仍保留实际等级；5 级不能委派权限，用户操作要求目标等级严格低于实际操作者，管理员专属能力保持。撤权对现有会话、CallerKey 和待执行任务生效。详见[权限、范围和上限](docs/steward-permissions.md)。

6 级协管可使用共享的端点与端点策略页面；5 级默认未获授权，可单独开放端点读取、标签、回退策略和路由配置读取。端点新增「用户自建网关」「协管自建网关」「错误填写」标签，保留原有多标签。审核列表支持按站内 ID 和 Discord ID 精确筛选；用户管理中的捐赠历史含已收起与终止记录，只展示安全摘要，不提供密钥控制。按来源管理默认显示全部来源和密钥状态。

管理员可在公益管理的独立「价格模板」界面查找、新增、编辑和删除模板，直接填写全部价格字段。管理员和获价格模板读取权限的协管可将模板复制到模型表单，按需修改后保存。
模型和模板支持按时区、星期和每日时段配置[周期折扣](docs/charity-discounts.md)。启用固定时段折扣后，周期折扣暂停；已受理请求保持受理时的价格。

绑定选择器显示已有连接，获授权管理人员可一次将一把捐赠密钥绑定到多个公益模型。管理员和获预置权限的协管可在独立界面维护主流渠道预置，具备绑定权限时可一次应用到已通过捐赠的全部密钥；自定义端点捐赠也可选择其他渠道模板，地址和协议匹配项优先推荐，来源和授权保持。缺少模型和已存在绑定会逐项提示。密钥、来源和绑定显示当前批准服务的失败暂停、等待及部分可用性，便于找到相应恢复入口。

平台模型可选择经 [Cloudflare Worker](docs/cloudflare-egress.md) 转发，各类上游无需逐个配置映射。自用模型默认开启、公益模型默认关闭；管理员和获路由配置读取权限的协管可查看实际加载的配置。未配置 Worker 时兼容旧 AI Gateway 映射。支持 Google AI Studio 和 Vertex AI 的官方 OpenAI 兼容入口，配置状态不代表上游连通性。

实验性[管理助手](docs/api-contract.md#78-experimental-ai-assistant)支持 Chat Completions API、外部 Responses API、已连接的 ChatGPT 账号及独立的 Codex 连接。管理员可设置默认来源、按用途覆盖或为具体协管另选来源；移除覆盖后恢复继承。来源不改变操作者权限，失败也不会静默切换其它来源。原有 API 配置继续可用；本地上下文与回复预留预算和上游输出上限分开设置。

连接 [Codex](docs/codex-agent.md) 时，在管理员 AI 设置发起设备码登录，再前往显示的官方页面完成授权。Go 服务负责轮询和加密保存凭据，无需外部 CLI。此来源只能绑定管理员对话或逐人选定的协管，不能通过全局／协管默认来源继承，不用于自动审批，也不进入自用或公益模型路由。真实 Business 账号授权与推理尚未验证。

连接 ChatGPT 时，先在管理员 AI 设置下载实例目标文件，再在有浏览器的电脑上运行仓库内登录助手：

```sh
go build -o nonbiri-chatgpt-login ./cmd/nonbiri-chatgpt-login
./nonbiri-chatgpt-login --target instance-target.json --output connection.json
```

Windows 使用 `nonbiri-chatgpt-login.exe`。打开显示的链接，授权 NonbiriAPI，再通过 HTTPS 将加密的 `connection.json` 导入同一实例，成功后删除传输文件。保留本机 host-ID 文件；重新尝试时请换一个输出文件名。一个实例共用一个 ChatGPT 连接，请求需要时自动刷新令牌，并按账号拉取模型目录；可用性取决于账号与当前预览政策。连接页面显示更新时间和当前令牌到期时间；公开接口未提供账号剩余额度及重置时间，请前往 [ChatGPT 用量设置](https://chatgpt.com/settings/usage)查看。本实例近 24 小时用量仅统计仍留存的已结束 ChatGPT 请求，包含此前连接，清理明细后会减少。详见[连接指南](docs/chatgpt-agent.md)、OpenAI [自托管说明](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms)和[预览限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)。

[内置预置](docs/ai-agent-presets.md)提供可编辑消息、记忆和工具说明。默认对话消息包含 `{{interlocutor}}` 和 `{{personal_memory}}`，既有自定义模板保持。对话仍默认关闭，每名获授权操作者有一个独立会话，可编辑和压缩上下文。全局对话／审批记忆仅管理员可修改；个人记忆由有工作区权限的本人和管理员维护，账号删除后继续供管理员留存，不进入普通账号自助导出。对话中的写操作须先批准完整计划，再核对当前权限和版本，整套提交或整套回滚。

自动审批独立控制，默认停用；预览只保存建议，自动模式可在确定性规则之后审批并绑定已有公益模型。只处理启用期间新提交或新修改的待审内容，不扫描积压、不提供手工入队。每次实际模型请求以共用 FIFO 排队并计入全站 RPM 和并发，不消耗个人 RPM 或积分。自动审批记录授权该配置的管理员。

捐赠审批页面及对应 AI 工具显示提交时的主流订阅／主流 API 类别和端点当前有效标签。

管理员可查阅完整助手请求和返回，并按确认范围手动清理。会话原文、记忆和累计 Token 统计作为管理员资产独立保留；AI 审批证据跟随对应捐赠生命周期。普通调用日志保持现有规则。

独立的管理操作记录从升级后开始，覆盖管理写入的成功、失败、拒绝及部分成功／无变化结果，区分网页人工、CallerKey 自动化、主流规则、AI 自动审批和经批准的 AI 计划，保留操作者与授权者快照、安全目标及结果。新记录保存操作时的对象名称、白名单字段实际前后值及关联影响；大批量变化保留准确数量和有界样本，旧记录未保存的事实不补造。普通读取不记。管理员可筛选汇总、下钻分页明细，并按筛选、时间或全部范围创建可恢复的分批清理任务。记录无自动到期，账号或资源删除后继续保留，不进入个人导出；清理自身摘要和截止点之后的新记录保留。

请求详情区分实际客户端 HTTP 状态、最终处理结果和已确认的上游状态，按实际观测保留失败阶段、安全原因、请求关联及流式进度，也覆盖管理助手和图片请求。缺失证据明确标注，原始错误的权限与隐私规则保持。详见[诊断契约](docs/api-contract.md#request-failure-observations)。

## 构建与开发

使用 **Go 1.26.9**、**Node.js 22.23.4+（22.x）、24.22.1+（24.x）或 26.12.1+（26.x）**、**npm 12.0.1** 和 Bash；Windows 使用 Git Bash。最终程序无需 Node.js 或 C 运行时。

```sh
npm --prefix web ci
npm --prefix web run build
CGO_ENABLED=0 go build -buildvcs=true -tags dist -trimpath -o nonbiriapi .
```

`-tags dist` 嵌入双站构建产物；不带该标记时提供开发占位页。[贡献指南](CONTRIBUTING.md) 集中说明本地检查、浏览器准备、共享 fixture、CI 范围和受保护分支流程。实现与受影响测试应同时更新。

## 配置与部署

[首次配置](docs/first-run-setup.md) 涵盖私有目录、加密密钥、Discord OAuth 和公共域名。将 [admin.env.example](admin.env.example) 复制到检出目录外，替换占位值并在启动前加载。数据库与对应密钥须配套保留。

新库默认开启维护并关闭公共功能，使用 schema 42。服务只打开精确当前结构的已有库；较旧、较新、未知或不完整数据库在迁移、修复和恢复写入之前拒绝启动。精确登记的 schema 16–26 与 33–41 来源需先保全完整恢复集，再由部署者主动调用同版本[独立升级器](cmd/nonbiri-upgrade-v1/README.md)的 `--check` 或 `--apply`；服务、启动脚本和部署助手不得隐式升级。账户导出使用格式 31；schema 按存储需要变化，不与每个软件补丁绑定。升级是单向的，不提供降级迁移；旧程序不能打开结构不同的升级后数据库，不以旧快照自动覆盖新接收的数据。源码契约不表示实例已发布或升级。

[部署指南](docs/deployment.md) 说明 systemd、代理、不可变产物、升级和完整快照恢复；启动变量及在线设置统一维护在 [配置参考](docs/configuration.md)。
